## O que é One-Hot Encoding? 🔥

Olá! Ótima pergunta! O **one-hot encoding** (ou "codificação one-hot") é uma técnica usada para transformar **dados categóricos** (como textos ou rótulos) em **números** que uma rede neural consiga entender e processar.

Pensa no seguinte: redes neurais só sabem trabalhar com números. Se você tem categorias como **Premium**, **Medium** e **Basic** (como vimos no contexto das camadas de saída), a rede não sabe o que significa essas palavras. Então precisamos converter isso em vetores numéricos.

### Como funciona na prática?

Cada categoria vira um vetor de zeros com um único **1** na posição correspondente. Veja:

| Categoria   | Vetor One-Hot       |
|-------------|---------------------|
| Premium     | `[1, 0, 0]`         |
| Medium      | `[0, 1, 0]`         |
| Basic       | `[0, 0, 1]`         |

Perceba que:
- O vetor tem o **mesmo tamanho** do número de categorias (3 categorias = vetor de tamanho 3).
- Apenas **uma posição** é 1, todas as outras são 0 — daí o nome "one-hot" (um quente).
- **Não existe relação de ordem** entre as posições. Premium não é "maior" que Medium — são apenas categorias diferentes.

### Quando usar? 🤔

Use one-hot encoding quando:

1. **Seus dados são categóricos sem ordem natural (nominais):**
   - Exemplos: cores (vermelho, azul, verde), tipos de animal (gato, cachorro, pássaro), ou as categorias do nosso exemplo (Premium, Medium, Basic).

2. **Você está preparando dados para a camada de entrada ou saída de uma rede neural:**
   - Na **saída**, como vimos no contexto, cada neurônio representa uma categoria e devolve uma probabilidade. O one-hot encoding é perfeito para representar o valor esperado (label) durante o treinamento.
   - Na **entrada**, se você tiver features categóricas (por exemplo, a profissão de uma pessoa), você também precisa converter em números.

### Quando **NÃO** usar?

- Quando a variável categórica tem **ordem natural** (ordinal). Por exemplo: pequeno, médio, grande. Nesse caso, usar one-hot faria a rede perder a informação de que "grande > médio > pequeno". Melhor usar **label encoding** (0, 1, 2) ou outras técnicas.
- Quando você tem **muitas categorias** (ex: milhares de códigos postais), pois o vetor ficaria enorme e esparso. Nesse caso, técnicas como **embeddings** são mais eficientes.

### Exemplo rápido com código 🧑💻

```javascript
// Suponha que temos os dados de saída (labels) para treinar
// Categorias: Premium = 0, Medium = 1, Basic = 2
const labels = [0, 1, 2, 0, 1]; // Exemplo: 5 amostras

// Convertendo para one-hot encoding manualmente
const numClasses = 3;
const oneHotLabels = labels.map(label => {
  const vector = new Array(numClasses).fill(0);
  vector[label] = 1;
  return vector;
});

console.log(oneHotLabels);
// Resultado:
// [[1, 0, 0],  → Premium
//  [0, 1, 0],  → Medium
//  [0, 0, 1],  → Basic
//  [1, 0, 0],  → Premium
//  [0, 1, 0]]  → Medium
```

Ou, de forma mais prática, usando o próprio TensorFlow.js:

```javascript
const tf = require('@tensorflow/tfjs');

const labels = tf.tensor1d([0, 1, 2, 0, 1], 'int32');
const oneHotLabels = tf.oneHot(labels, 3); // 3 = número de classes

oneHotLabels.print();
// [[1, 0, 0],
//  [0, 1, 0],
//  [0, 0, 1],
//  [1, 0, 0],
//  [0, 1, 0]]
```

### Resumindo 🎯

O one-hot encoding é como se você desse "tradutor" para a rede neural: ele pega categorias que são texto ou rótulos e transforma em números que a rede consegue processar. É essencial quando estamos trabalhando com **classificação** — exatamente como no exemplo do contexto, onde a rede precisa decidir se um perfil é Premium, Medium ou Basic com base nas probabilidades de saída.
